# Multi-Instance Cron Audit

`openclaw cron list` shows only the current instance's jobs (bare invocation; single-instance targeted query works via `/usr/local/bin/openclaw cron list --port <port> --token <that instance's gateway.auth.token>`, 2026-09-30 verified). This server runs multiple OpenClaw instances at `/data/agent/openclaw_<name>/.openclaw/`; server-wide asks (所有实例 / 所有定时任务) must cover every instance's state. For targeted single-instance add/edit/list/run, the CLI works directly with `--port <port> --token <该实例 gateway.auth.token>`（坑与用法见 openclaw-automation-jobs 步骤 5）——轻量查询单实例时优先用它，全实例盘点仍走本流程的 DB 副本。两个解析/机制陷阱（10-08 实测）：① list 表格把长任务名截断（`morning-knowledge-dis…`），按完整任务名 grep 必落空——按截断前缀匹配取第一列 jobId；② `subagents.allowAgents`（sessions_spawn 目标白名单）是**实例内**机制，agent id 按本网关注册表解析，填其他实例的 agent id 只是永远无法解析的死条目——跨实例派单走网关 API（`openclaw agent --agent <id> --port --token`，env -i 全净环境；10-08 实测 jwh 默认拒绝 + data_group 派单成功）。

## Steps

1. Enumerate instances with `ls -d /data/agent/openclaw_*/`; per-instance agents with `ls <instance>/.openclaw/workspaces/` (`main` is the built-in default agent). Run `/data/agent/ops/status-all.sh` when live instance/port/status is needed.
2. Read each instance's cron jobs from a copy of its state DB:
   - External sqlite3 cannot open live state dirs (policy error). Copy `openclaw.sqlite`, `openclaw.sqlite-shm`, and `openclaw.sqlite-wal` from `<instance>/.openclaw/state/` into a per-instance scratch dir under /tmp. Do not look for `.openclaw/cron/jobs.json` — store_key references it but the file does not exist. ⚠️ 文件副本还可能滞后（WAL 未 checkpoint）：刚创建的 job 在几秒后拷的副本里可能不存在——2026-10-12 GTM/GYL/PJT/QD 部署实测：CLI `cron run` 已回 ok:true+jobId，副本里两实例报 job 未找到、其余 status=None，而网关侧执行正常、receipts 稍后出现。部署期排障以 CLI `cron list/runs/run` 为准（后者须按截断前缀匹配提取 jobId，表格会截断长任务名）；文件副本仅用于长周期审计。A fresh copy can lag the live DB (WAL not yet checkpointed): a job confirmed via gateway CLI (`cron list --port --token`) may be missing from the just-copied file — re-verify through the gateway API before concluding a job is absent (10-08 GYL/PJT 误报实测)。
   - Open each copy read-only with python3's sqlite3 module (`sqlite3.connect("file:<path>?mode=ro", uri=True)`); the sqlite3 CLI is often not installed.
   - `SELECT name, agent_id, payload_kind, enabled, job_json, state_json FROM cron_jobs ORDER BY agent_id`. Schedule is inside `job_json` (`schedule.everyMs` / `schedule.cron` / `schedule.at`); run state inside `state_json` (`lastRunAtMs`, `nextRunAtMs`, `lastRunStatus`). payload_kind values: command, agentTurn, heartbeat, skillCollectionReview.
3. Report per instance: schedule, enabled, last/next run (format Asia/Shanghai), status. Sum enabled vs disabled and error counts. Stale `lastRunAtMs` on recurring jobs means the instance was offline during that gap — report the offline gap, not a job failure.
4. For "all scheduled tasks" asks, cover system level separately: user crontabs (`crontab -l` per user), `/etc/cron.d`, `systemctl list-timers --all --no-pager`. 2026-09-28 起实例专属活跃任务在 `ocs_<x>` 用户 crontab（GTM/PJT/QD 归属迁移，见 instance-identity-isolation），root crontab 只剩 XMT/TeamS 线、furnace curls 与已迁移条目的迁移标记注释——审计两侧都查。

5. For server-wide error sweeps (e.g. 流式卡片更新失败, send/delivery failures), read each instance's gateway runtime log at `/data/agent/ops/logs/openclaw_<name>.log` — it is the nohup stdout/stderr redirect; verify one via `readlink /proc/<PID>/fd/1` (PID from `/data/agent/ops/status-all.sh`). Do not use `<instance>/.openclaw/logs/` — it holds only stale config-audit/commands.log. Grep it for the error class (e.g. `Started streaming|Closed streaming|error|fail`), and check per-instance config at `<instance>/.openclaw/openclaw.json` for the related settings.
6. start-all.sh truncates these logs on every restart (`> "$log_file"`, no rotation): read each log's first line timestamp to know the coverage window; pre-restart errors are unverifiable from logs alone — use step 7 for activity questions. All instances share one OpenClaw install (`/opt/openclaw`), so plugin/channel code (e.g. feishu streaming) and version are identical server-wide; behavior differences come from config, not version skew.
7. Per-agent activity over a window spanning a restart (e.g. "从昨天下午5点到现在各子agent执行了什么" / 播报合规审计): the forensic source is `audit_events` in each instance's `state/openclaw.sqlite` (same /tmp copy + `mode=ro` python3 as step 2) — it survives log truncation. Key columns: `occurred_at` (epoch **milliseconds**, /1000 then format Asia/Shanghai), `agent_id`, `kind` (`agent_run` / `tool_action` seen in practice), `tool_name`, `session_key`, `status` / `error_code`. Group by agent_id×kind for per-agent load; filter `kind='tool_action'` ordered by time for a run trace. Per-agent broadcast/tool audit (verified 2026-09-20/22, 28 agents × 3 rounds): each agent's `agents/<id>/agent/openclaw-agent.sqlite` (note the `/agent/` path segment) `transcript_events` table IS populated, and this agent DB is NOT policy-blocked — read-only sqlite3 direct query works; only `state/` DBs need a /tmp copy. Procedure, script and classification rules live in the `agent-broadcast-audit` skill (its scripts/audit.sh) — single authoritative home, don't duplicate here. 语义级提取（如"某天各 agent 修了什么/遇到什么报错"）用 JSON1：`json_extract(event_json,'$.message.role')` 分角色、`json_each(event_json,'$.message.content')` 展开 text/toolCall 块——**必须先加 `json_valid(event_json)=1`**，坏行会让 json_each/json_extract 直接报 malformed JSON（2026-09-21 实测）；会话↔key 映射查 `session_windows`（session_key 含 `:cron:` 即定时任务会话，furnace agent-daily 的 SQL 即此套路，可抄 `/data/opt/OpenClaw-bot-review-furnace/lib/agent-daily-source.ts`）。 Limits to state in the report: no tool arguments are recorded (proves activity type/count/status, not literal commands — 独立播报走 exec lark-cli 时无法从审计逐字核对), and channel message text is absent. Worked example (播报合规): 配置面 grep `{{CHAT_ID}}` in each sub-agent AGENTS.md (unreplaced = independent-announcement channel never enabled) + 行为面 audit_events counts; an agent with zero `tool_action` rows only handled tool-free instant replies, which the 播报 rule exempts.
   Completion: per-instance per-agent windowed activity table with evidence bounds stated. 修复侧（按审计缺口批量补 chat_id/环境嵌入等 AGENTS.md 配置）走 batch-agentsmd-rollout 的数据驱动变体（chatid-harvest.md 双源交叉验证）。
