# knowledge/ — 经验蒸馏体系样例

> 这不是"文档目录"，而是平台知识管线的**产物样例**——展示每日踩坑如何被结构化沉淀、
> 又如何反哺回 Agent 的上下文。生产环境中本体系由 `morning-knowledge-distill` 夜间定时任务驱动。

## 知识管线全貌

```
各 Agent 每日运行
   │  踩坑/解法/业务知识写入各自 memory/YYYY-MM-DD.md
   ▼
morning-knowledge-distill（夜间定时任务）
   │  读取全部子 agent 当日日报中的坑与解法
   │  蒸馏为结构化 lessons + 维护 INDEX 索引
   ▼
按月滚动的 lessons 文件
   │  ① 喂回 agent 上下文（AGENTS.md 引用 / 技能引用）
   │  ② 高频/通用模式 → 升级为技能（skills/ops/*）
   │  ③ 制度性教训 → 升级为 AGENTS.md 条款
   ▼
次日同类问题：agent 直接命中经验，不再付学费
```

## 本目录文件

| 文件 | 说明 |
|---|---|
| `2026-10-15-lessons-sample.md` | 真实 lessons 日样例——含"幽灵身份"发现（zxy agent 已从配置删除但其定时任务链仍在运行）等当日报障记录 |

## lessons 文件格式约定

每条 lesson 包含四要素（缺一不可，否则无法被 agent 复用）：

```markdown
## <一句话标题>（<日期> <排查耗时>）

- 事实：<发生了什么，含关键证据路径/命令输出>
- 结论：<根因是什么>
- 教训：<下次如何提前识别/预防>
- 处置：<已做什么/待做什么，含回滚方式>
```

## 升级路径判定

| 场景特征 | 去处 |
|---|---|
| 排障步骤可复用（换台机器还会遇到） | `skills/ops/<新技能或既有技能>` |
| 属于行为规范（agent 该做/不该做什么） | `governance/AGENTS.md.template` 对应章节 |
| 一次性事件但有取证价值 | 本目录 lessons 文件 |
| 影响面跨实例/需要人审批 | 变更管理单（范本见 `ops/mcp-rollout-202610/`） |

## 为什么"经验不过夜"

Agent 会话之间无状态——今天踩的坑，明天的会话完全不知道。不沉淀的后果是：
同一类故障在不同 agent、不同日期反复发生，每次都从零排查。
蒸馏管线把"个体的踩坑"变成"组织的记忆"，这是平台能持续变快的根本原因。
